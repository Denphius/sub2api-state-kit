# 构建与部署

本仓库保留源码覆盖包，并在 Release 提供**完整源码和 Linux 部署包**。不想应用补丁或编译的用户先看 [完整部署版](full-release.md)。下文介绍增量源码构建；仅对固定上游 v0.2.6 提供校验，不要直接覆盖其他版本或带自定义修改的生产源码。

## 生成源码

```bash
python3 scripts/prepare.py ../sub2api-state-source
cd ../sub2api-state-source
```

依赖 Git、Python 3 和 GitHub 网络连接。脚本也支持 `--upstream-source /path/to/upstream-mirror` 指定上游 Git 镜像；仍然验证相同提交及文件哈希，不复制镜像的工作区改动。目标目录必须不存在。

## 构建

固定基线的后端要求 Go 1.27 或更高兼容版本，前端使用 Node.js 与 pnpm；容器构建版本以生成源码中的 Dockerfile 为准。

```bash
docker build --build-arg VERSION=0.2.6-state-kit.0.1.0 -t sub2api-state-kit:0.1.0 .
```

也可按上游文档单独构建前端和 Go 服务。无需独立 STATE 服务，不新增端口，不需要新的数据库迁移。

## 接入现有部署

先备份数据库和部署配置，在隔离环境使用自己提供的测试账号验证。使用新构建镜像替换应用镜像，保留原数据库、Redis、卷、网络、域名和密钥配置。不要把上游示例配置直接覆盖现有配置。

首次保持账号 STATE 开关关闭，检查原有业务，再只开启一个需要测试的账号。按 [使用说明](usage.md) 配置动态池和固定业务代理。遇到问题先关闭该账号功能；回滚应用版本前应保留数据库备份，并按对应上游版本检查兼容性。

完整发布版附带空白新安装的 Compose 示例，不附带任何人的生产配置或真实连接信息。多副本部署没有跨进程采集锁，可能重复采集；请求路径也会增加账号配置数据库读取，需要自行评估负载。

后续升级请重新合并并验证扩展；直接切换回官方镜像会失去本扩展功能。
