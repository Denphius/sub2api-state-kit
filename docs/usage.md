# 使用说明

以下直连功能适用于最新 `main` 源码；旧 v0.2.0 完整部署附件需要用最新源码重新构建后才能使用。本次没有替换旧 Release 附件。

1. 系统设置 → 网关服务 → Codex 设置：打开 STATE 总开关，设置全局动态 IP 池。使用你自己的完整 HTTP / SOCKS5h 代理 URL；不需要导入一堆出口 IP。留空保存保留现有连接。
2. 账号管理 → 编辑 OpenAI OAuth 账号：先保存业务代理设置（固定代理或“无代理”），再重新打开编辑窗口。“无代理”表示复验和业务请求从当前服务器直连，不影响全局动态池采集。
3. 在 STATE 票据区域选择 Pro（292）或 Team（332），开启账号功能并点击该区域的保存。
4. 等待票据显示可用。可以点击重新获取，页面仅展示摘要，不展示完整 STATE。
5. 客户端保持原来的 Key 和 Base URL。

代理用户名中的 `{sid}` 每次尝试生成新值；1024proxy 的 `-sid-...-t-N` 格式也会刷新 SID。不同 SID 不保证不同出口 IP。动态代理只用于采集，复验和业务请求保持账号固定代理或服务器直连。切换这两种业务出口会使旧票据的路由绑定失效，需要重新采集复验。直连绑定不探测公网 IP，服务器迁移或出口 IP 改变后应手动重新获取票据。

全局开启不会自动开启账号。新建、导入、复制的账号不会继承启用状态。旧版账号内的动态代理不再参与采集，升级后应在全局池手动填写一次。

缺少有效票据时，仅暂停已启用账号的目标模型调度，其他账号和模型保持原流程。更改套餐会使原票据失效并重新采集；更换全局池保留有效票据和原到期时间，未完成的旧池任务不能发布结果。

票据成功保存数据库后才进入内存。重启会恢复仍有效且绑定配置相符的票据；续期失败不延长原到期时间。账号卡片展示续期、冷却、剩余时间和守护触发摘要。

动态守护只依据完整成功响应的实际模型或有效的 312 字节 STATE 信号，不读取回答文字判断。HTTP 观察缓冲上限为每个事件/JSON 1 MiB；超大、损坏或未完成的响应不被当成降质证据。守护不重放业务请求、不重写已发送的结果。

全局代理存在系统设置，账号功能和票据存在 `accounts.extra` 的服务端私有字段。接口及审计进行脱敏，数据库本身仍含敏感数据，勿公开备份。
